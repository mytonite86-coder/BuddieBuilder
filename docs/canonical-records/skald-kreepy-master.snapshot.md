## 0. Portfolio record-control rule

This is the single portfolio-level index and sequencing authority. Each implemented product family retains one detailed master beneath it. Supporting registries, profiles, baselines, decisions, and verification reports may define focused contracts or evidence but must point back to the appropriate master and must not become competing status boards.

Before any portfolio work block:

1. Read this portfolio master.
2. Read every affected product master.
3. Preserve stable IDs, protected access, customer history, and product boundaries.
4. Update affected product masters first, then reconcile this portfolio summary.
5. Cite complete revision IDs in the final status report.

## 0.1 Mandatory Portfolio Work-Block Continuity

Any genuinely active block created before this revision must add the inheritance pointer and create a handoff at its next session boundary before continuation.
